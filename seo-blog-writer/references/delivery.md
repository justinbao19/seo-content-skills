# Delivery

Follow the user's requested destination and the site's real content schema before any generic example here. A local draft is a draft; publishing, uploading, outreach, and recurring promotion require the relevant authorization.

## Final artifact

- Save the complete article in the requested path and format. If none is specified, use `seo-output/<slug>/article.md` in the task workspace. Keep substantial research and QA notes nearby when they help review or resumption; do not generate empty package files to satisfy a mode count.
- Populate only frontmatter fields the destination supports. Use a clear, faithful title and description. Author, publish date, update date, tests, and review status must reflect reality. Keep locale, slug, canonical, and related translations consistent with the site's rules.
- Add structured data only when the site supports it and the markup accurately describes visible content. An FAQ section and FAQPage JSON-LD are not defaults or guarantees of search presentation.
- Include source links where the reader can verify consequential claims. Preserve citation/provenance notes separately if the publication strips inline citations.
- For a WebP destination, deliver genuine WebP references and the image QA result from [drafting](drafting.md). For other destinations, use their image contract.
- If both English and Chinese versions are requested, edit each as its own article. Keep facts, numbers, and positions aligned while allowing natural differences in sentence order, examples, titles, and pacing. Check links and locale-specific availability in both.
- Where relevant, report useful follow-up measurements such as indexing, search queries, engagement, or AI referrals as **future observations**, never predicted outcomes.

Report what was written, where it is, what was checked, and what remains uncertain. Do not treat a prepared file or draft schema as a published result.
