# SEO 双向维护与兼容分发

当前两个活跃维护入口是本仓库 `skills/seo-blog-writer` / `skills/seo-geo-qa` 与 `AIhubmix/product-skills` 的同名目录。团队入口保留自身 SKILL、宿主 metadata 和 workflow 适配。

`justinbao19/seo-content-skills` 保留公开兼容分发，本次迁移后不再独立编辑通用源；通用变更回到个人聚合库或团队入口维护。其原有四项技能和旧安装方式保留。两个更早的独立仓库继续归档只读。

## 每次变更

1. 读 `sync-map.json`，取得所有启用端的新版本，检查本地修改；依据固定源内容和上次基线比较两边变化。
2. 合并通用方法与脚本，保留团队入口、业务核验边界和组织引用。来源说明与已知结构差异不代表规则冲突。
3. 仅同步绑定 Skill 的必要资源及相关回归；不整仓镜像，不公开组织资料。Core 仍由 `AIhubmix/aihubmix-design` 单独维护。
4. 在各端验证受影响的脚本、引用与独立安装。兼容分发在此次同一维护任务内更新；它不是第三个任意编辑的主源。
5. 提交注明来源、源 commit、Skill 和 sync id，遵守保护分支。内容一致跳过空提交；核验目标 commit/PR 后再推进基线。
6. 报告未同步目标、未合并 PR 与真实冲突；保留已有授权，不重复请求同一对应同步的确认。

本流程由维护 Agent 执行，没有配置后台监听、GitHub Actions 或定时任务。网页单独修改不会自动传播。需要无人值守同步时另行配置机器人创建 PR 和验证，不用强制覆盖消解冲突。

个人聚合库当前为私有。公开兼容入口只接收原有可公开的通用 SEO 资源，不接收其他私有技能、运行状态或团队材料。新的公开分发集合需核对来源与权利。
