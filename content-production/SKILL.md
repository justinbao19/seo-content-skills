# Content production

Match the requested deliverable, language, audience and existing approval checkpoints. A full article task includes a finished draft and relevant checks; a topic, edit or review request stops at that requested output. Do not create extra approval checkpoints or publish merely because you produced a package.

1. Read supplied context and use the installed skill matching the task: `seo-blog-writer` for site SEO research/drafting, `writer` for general articles, a platform writer for channel conventions, or `justeng-wechat` for JustEng. These are separately installed capabilities, not files assumed inside this package. If unavailable, complete the applicable work directly and state the actual coverage.
2. Research material claims; preserve source context, author evidence and uncertainty. Write in the audience’s language. Use the matching bilingual localizer when translating supplied text.
3. Review evidence, reader value, whole-piece voice and destination constraints. `content-qa` can provide a separate editorial review; `seo-geo-qa` provides technical checks when applicable. Independent delegation is optional when supported and authorized; do not require a named model or host-specific spawn API. Without a separate reviewer, label the pass as self-review.
4. Fix demonstrated issues, then recheck changes and outstanding findings. Do not inflate link counts, FAQ, word counts or keyword density to satisfy default templates.
5. Deliver the requested files and relevant evidence/QA notes. Distinguish technical results, editorial review, human approval and actual publication. Public uploads and publishing use existing authorization for those actions.

After publication, an installed `seo-geo-qa` can audit the supplied live URL when requested. It is a separate task with its own dependency and coverage report; do not claim it was executed on an unpublished draft.
